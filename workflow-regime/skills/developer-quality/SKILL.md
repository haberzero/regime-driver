# Developer 质量自律（精简）

> 你在受监督流程中执行节点。本 skill 只要求你在**实现（implement）**与**收尾（wrap）**
> 节点交付前做最低限度的自查——完整审查由独立的 reviewer 负责，你不需要替代它，
> 但你有责任**不交付明知有问题的产物**。

## 一、实现节点自查（写代码时对照）

1. **无兜底**：不做 `except: pass`、不静默取默认值掩盖错误、不用 `hasattr` 探测能力。
   错误应显式抛出（ValueError/自定义异常）并给清晰信息。
2. **无历史包袱**：不"顺便保留"被新逻辑取代的旧分支；不写兼容 shim。
3. **无双通道**：同一决策只有一条路径，不新旧并存。
4. **参数校验**：公共方法入口校验非法参数（负数/空/None/越界），抛 ValueError 而非崩溃。
5. **边界覆盖**：空输入、单元素、满容量、并发竞争等规格要求的边界必须处理并测到。
6. **命名与结构**：类/方法名表达意图，不出现单字母晦涩名（除极短局部变量）；内部结构
   用命名类型（dataclass/namedtuple）而非裸 list/dict 传语义。
7. **线程安全**（若规格要求并发）：共享状态用锁保护；不丢数据、不超卖、无竞态窗口。
8. **不留 TODO/临时绕过**：不写 "先这样"、"临时方案"、"快速实现" 字样。

## 二、收尾节点自查（交付前）

1. **残留清理**：删临时文件、调试打印、`__pycache__`、无用 import。
2. **全量验证**：容器内跑完 `python3 -m pytest <test_file> -q`，确认 N passed，汇报给出
   精确的 "N passed" 行。
3. **文档一致**：若规格要求，产物注释/docstring 与实际行为一致，不夸大不遗漏。
4. **测试真实**：断言是真实断言（断言具体值/异常/属性），不是空断言或恒真断言；
   规格要求的每个边界都有一条测试。

## 三、与 reviewer 的分工

- 你负责**不交付明知有问题的产物**（本自查）。
- reviewer 负责**独立审查与判定**（advance / 要求返工）。
- 若自查发现无法自主修复的问题，在汇报中如实标注"技术债/待决点"，不要掩盖。
