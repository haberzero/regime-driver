# 你能做什么：能力一览

> 本篇按"你能达成什么目标"组织，不按命令/参数组织。所有操作都可以通过控制对话框对话完成；
> 底层命令只在你想手动操作时用（细节见"查询参考"）。
>
> **想看全量能力索引**（每个能力 → 入口 → 使用场景 → 验证方式）：见[能力地图](../capabilities.md)。

## 一、用对话完成任务

- **启动一个任务**：说"跑 code_workflow 实现某某功能"，对话框启动并跟踪。
- **看任务进度**：随时问"现在跑到哪了"、查看事件。
- **和某个工作会话对话**：直接和一个 opencode session 单独交流（`talk`）。

> 为什么这么设计：你关心的是"任务完成了没有"，而不是"哪个节点在哪个 session 上"。
> 对话框把后者替你处理了。

## 二、官方工作流程模板：制度驱动规划的样板

为了理解"你的编程指令如何被制度化地执行"，先看官方自带的流程模板 `code_workflow`。
它不是"一个 agent 自由发挥"，而是一条**结构化的制度路径**：

```
understand → read_code → design → implement → test → wrap
   (干活)       (干活)     (审查)     (干活)     (审查)   (干活)
  developer   developer   reviewer  developer  reviewer  developer
```

- **干活与审查分离**：`developer`（干活）走 understand / read_code / implement / wrap；
  `reviewer`（审查判定）走 design / test。审查不过关，流程**不前进**。
- **技能按节点注入**：design 节点注入 `design-philosophy`，test 节点注入 `code-review`——
  给审查角色它恰好需要的规则，不常驻、不稀释。
- **全程记录**：每一步（节点进入/完成/审查判定/流转/最终结果）都写入报告与事件账本，可复盘。

> 逐步展开这张表（每个节点做什么、审查如何判定、为什么这样走）见
> [控制对话框：对话背后发生了什么](00_dialog_control.md)。

## 三、用对话设计流程与制度

- **用自然语言设计流程**：说"设计一个先实现、再审查、再测试的流程"，对话框编译并注册。
- **设计完整运行制度**：说"设计一个带自动中断续跑的流程"，对话框按你的监督/人工确认要求，
  生成**整制度**（flow + roles + watchdog + handover 合一），用 `--regime-name` 按名运行。
- **查看已注册流程与制度**：`flow list` / `regime list` 列出全部可运行项。
- **让对话框代写 JSON**：你不必手写 JSON——描述意图即可（意图级设计；提到"审查前必须
  跑测试"会在审查节点加 `verify`，提到监督/人工确认会生成 watchdog 配置）。
- **扩展你的体系**：`~/.regime/hooks.py` 插件统一注入 hooks/看门狗规则/自定义工具；
  对话框 `hook list/path/reload` 管理与热重载。

> 为什么这么设计：流程/制度是体系的心脏，但"怎么写配置文件"是技术细节。对话框把它变成一句话的事。

## 四、监控与复盘

- **全局态势**：一句话看 worker 健康、运行中的任务、会话情况（`status` / `sessions`）。
- **事件回看**：看最近发生了什么（`watch` / `events`）。
- **报告看板**：把多次运行汇总成可读报告（`report`）。

> 为什么这么设计：系统会自动记录每一次运行（报告日志 + 事件账本），你能复盘"当时为什么这样走"。

## 五、监督与恢复（自动）

- **进程外监督**：系统自带一个独立监督器，周期性检查 worker 健康、任务是否停滞、有没有超时。
- **自动纠正**：发现问题按既定阶梯处理（提示/中止/换模型/重启），不需要你盯着。
- **人工确认点**：审查者需要你拍板时 workflow 冻结，对话框 `decide <workflow> <yes|no>` 应答；
  无人值守时按超时默认值自动兜底（不会无限等待）。

> 为什么这么设计：卡死/打转是 agent 工作的常见问题。让独立的时钟盯着，而不是靠人；
> 真正需要人判断的关口，把决定权留给有权限的那个人。

## 六、并发与隔离

- **多任务并行**：同时跑多个任务（`run-many`）——黑板按 workflow id 隔离、互不干扰；但同一
  worker 的文件系统共享，可能发生文件碰撞，需要产物隔离时用下面的工作区隔离。
- **工作区隔离**：每个任务在独立的 worker 实例里跑，产物互不污染（`drive --workspace` / 并行任务）。

> 为什么这么设计：真实使用中会有多个任务。物理隔离保证它们不互相踩踏。

## 七、健康与自检

- **一键自检**：`doctor` 检查 worker 健康、模型密钥、官方模板是否就绪。
- **配置就绪**：`regime scaffold` 一条命令部署官方模板，`doctor` 验证。

> 为什么这么设计：减少"配置半天才发现某个环节错了"的挫败感。

## 八、资源治理

- **自动清理会话**：长期运行后，可用一句话让系统清理累积的会话（`sessions --cleanup`）。
- **报告保留**：journal 可设保留策略，防止无限增长。

> 为什么这么设计：长期运行会累积会话记录；治理工具让你不必手动清理。
