# 架构原则与设计理念

> 本文是 regime-driver 的架构原则与设计理念（Divio "解释"类）。
> 面向需要理解系统为何如此设计的开发者。
> 覆盖七条核心原则，每条以"约束→决策→后果"陈述设计理由。
> 前置知识：状态机概念（见 `core/state_machine.py`）、对等网络总貌（见 `02_statechart_network.md`）。
> 边界划分见 `03_boundary.md`；模块实现见 `subsystems/`。

regime-driver 是一座"制度流程机器人"：把组织制度编译成确定性的对等状态机网络，
由无智能的宪法状态机监督有智能的工作流单元。其设计理念可概括为一句话——
**智能负责自由裁量，机制负责确定性约束**。七条原则从流程表示、内核抽象、
监督边界、自我监管四个层面展开，共同保证系统既可灵活定制、又无法自我失控。

## 1. 编译制度流程为状态机（确定性的流程表示）

**约束**：AI 直接按提示词执行流程，结果不可验证，易打转、易越界。
纯靠提示词约束无法证明流程合规，也无法审计。

**决策**：把制度流程编译为状态机（`StateMachine`）。
每个节点声明确定的后继 `next` 与分支 `branches`；
遍历受限在 `successors` 返回的合法目标内，禁止回退与自环。
编译时即校验后继存在性，发现环立即拒绝（`flow_path` 检测循环）。

**后果**：流程成为可验证、可审计的数据结构。
LLM 只能在合法后继内推进，无法任意跳转。
配置错误在启动前暴露，而非运行中失控。

## 2. 内核角色无关（role-agnostic）

**约束**：具体角色（开发者、审查者）随用户场景与需求变化，并非稳定内核。
把它们写进内核，每次新增角色都要改内核。

**决策**：内核只认**抽象角色 id**，不关心谁叫开发者、谁叫审查者。
角色由用户经 `RoleRegistry` 注册，绑定 agent、生命周期策略、技能与工作目录。
`developer`/`reviewer` 只是默认注册的角色实例（`role.py`）。

**后果**：角色成为用户特化数据，而非内核概念。
新增角色零内核改动，内核专注于 session、节点、交接、流转等通用机制。

## 3. 确定性门把关（确定性判断，非 LLM 自由裁量）

**约束**：LLM 输出结构化 JSON，但可能字段缺失、动作越界、自相矛盾。
若全部采信，破坏性动作可能被低置信度触发。

**决策**：引入**确定性门**（`core/contract.py` 的 `gate_reviewer_verdict`）。
按动作白名单校验动作与 verdict 的一致性、字段关联、
置信度下限——越重越具破坏性的动作要求越高（如 `advance` 需 0.5，`abort` 需 0.7）。

**后果**：LLM 可提出建议，但最终放行由纯函数判定。
无法通过模糊匹配逃逸，无法用低置信度触发重动作。
同一套白名单机制也用于监督侧（`supervisor.py` 的 `gate_meta`）。

## 4. 宪法 = 无智能状态机 + 根不变量运行时强制（自我监管的反循环）

**约束**：宪法需要可覆写以适应用户，但若完全可覆写，AI 能关掉自己的监狱。
可定制与安全不可动摇存在张力。

**决策**：宪法本身**不特殊**，只是一个无智能的状态机
（`app/constitution_unit.py`），通过信号与工作流交互。
但三条**根不变量**从宪法层剥离，上移到运行时强制（I1/I2/I3）：
至少一个活跃看门狗、至少一条不可关闭的 STOP/Esc 通道、元迭代上界。

**后果**：具体检测策略、阈值、乃至哪个状态机充当宪法都可覆写。
但任何用户宪法都无法移除紧急停止能力。
自我监管是**反循环**的：可改策略，不可改监狱本身。

## 5. 进程外监督（独立时钟）

**约束**：卡死检测基于"事件缺席"与超时，需要独立时钟。
进程内的监控线程与卡死的被监督进程同生共死，无法自救。

**决策**：监督放**进程外**的 `supervisor.py`，自带独立时钟与容器控制。
每轮循环摄入事件、做 T1 健康检查与 T2 会话停顿检测、
强制 deadline，并按纠正阶梯升级（nudge→abort→fallback→restart→human）。

**后果**：即使被监督进程完全卡死，supervisor 仍能检测并重启。
进程内宪法负责流程级控制，进程外监督负责进程级兜底，
两层时钟互不共享生命周期。

## 6. 可自我修改元系统（FlowRegistry 热重载 + 反循环门禁）

**约束**：流程需要随运行演进（用户设计、文件加载、在线调整）。
但无界自我修改会陷入无限自省循环。

**决策**：`flow.py` 的 `FlowRegistry` 是命名流唯一真源，支持**原子热重载**。
新版本先编译 + 深度校验，通过才替换注册项；
运行中的工作流持有旧 `StateMachine` 快照，永不被改动。
所有加载/重载经深度校验，含循环检测与节点总数上界（反循环门禁）。

**后果**：流程在线可改，改动要么整体生效、要么整体拒绝。
在途工作流不受重载干扰。自我修改有界，
无法通过自改制造无限循环。

## 7. 事件驱动对等网络（线程/信号/黑板，多单元互驱）

**约束**：多个状态机需互驱、互发信号、共享状态，且不能互相阻塞。
发派 session 后 LLM 工作在容器内异步执行，状态机线程空闲可轮询。

**决策**：每个状态机是**单线程混合循环**
（`app/statechart_runtime.py`），同一循环处理 session 轮询、消息队列与超时。
单元经 `Runtime` 走双向信号/事件总线（默认异步），
经黑板（`app/blackboard.py`）共享状态并订阅变更。

**后果**：宪法状态机可向工作流发 STOP，工作流回送时间戳与回复。
多 workflow 并发互不影响（黑板按工作流 id 隔离）。
单循环消除长阻塞，保证等待时仍能响应他方信号。
