# regime-driver 机制归属边界审查（内核 vs 用户特化）

> 状态：审查中（v2 修正）
> 日期：2026-08-04
> 目的：明确系统里哪些是"内核（通用机制，与角色无关）"，哪些是"用户特化（角色/流程/节点自定义）"。
>   纠正两点：① 把"审查者/开发者"当内核概念的偏差；② 把本可自定义的机制写死的倾向。
> 关联：`docs/ARCHITECTURE-v2.md`（交接模型）、`docs/ARCHITECTURE-v3.md`（策略可编程）

---

## 1. 核心认知修正（用户纠正）

### 1.1 节点 ≠ 角色
- **角色分离 = session 分离**（不同角色关注不同对话空间）
- **节点分离 = skill 注入 + 需求内容分离**（同审查者可负责不同节点）
- 同一个角色（session）负责多个节点完全合理：角色不变，节点变。

### 1.2 开发者和审查者没有本质区别
从"自定义角色、自定义流程、自定义节点"的角度：
- **内核不关心谁叫开发者、谁叫审查者**。
- 它们只是**用户特化的自定义角色实例**。
- 内核只认识抽象的：session、节点、交接、流转。

### 1.3 "防双失忆"也是策略，不是宪法
- 有些使用者可能允许双失忆。
- "审查者流转时锁开发者"是**用户自定义策略**，**不是内核写死**。

## 2. 内核（通用机制，与角色无关，定死）

| 机制 | 说明 |
|---|---|
| session | 一个"会累的对话个体"，有生命周期（自评/交接） |
| 节点 | 一个工作单元，声明 skill 注入 + 需求内容 |
| 交接（Handoff） | session 之间的状态传递（结构化、可审计） |
| 流转 | 节点之间如何推进（状态机） |
| 安全监控 | 死循环/卡死检测 + abort（宪法层） |
| 确定性门 | verdict/action 白名单（宪法层） |
| 收敛检测 | 质询打转检测（宪法层） |

## 3. 用户特化（可自定义，与角色绑定）

| 机制 | 说明 |
|---|---|
| 角色定义 | 一组 session 生命周期策略 + skill 集合 + 工作目录 |
| 节点→角色映射 | 哪个节点由哪个角色负责 |
| 流转策略 | 何时切换 session、是否允许双失忆 |
| 脑容量阈值 | 40%/70% 等 |
| 交接模板 | 正常/紧急交接文档格式 |
| 自评协议提示词 | 自评的 system prompt |

## 4. 当前最大偏差

代码里 ~191 处 `developer`/`reviewer` 硬编码，**把"审查者/开发者"当成了内核概念**。
正确做法：内核只认识**抽象角色 id**，`developer`/`reviewer` 是**用户注册的角色实例**。

## 5. 重构方向

- **内核通用化**：把 `Actor`/`role` 从 `developer|reviewer|machine` 改为**任意角色 id**。
- **角色注册**：用户定义角色（策略 + skill + 目录），节点映射到角色。
- **流转策略可自定义**：session 切换、是否锁锚点，都是用户策略。
- 保留宪法层：安全监控、确定性门、收敛检测、节点预算。
